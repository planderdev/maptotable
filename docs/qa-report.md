# 검수 결과

검수일: 2026-11-21 (Asia/Seoul). Windows, PHP 8.5.5, Playwright 1.56.1, 설치된 Chrome과 WebKit 26.0에서 로컬 PHP 서버를 검사했습니다. 운영 사이트에 배포하거나 검수 입력을 게시하지 않았습니다.

## 실행 검사

- `npm run build`: 정적 에셋 준비, PHP 13개 문법 검사, 사진 소유 ID·질문 원문·브랜드 값·주소 파일·폰트 존재 검사 통과.
- `npm test`: 246개 검사 통과. 네 화면의 AOS 요소를 실제 스크롤로 표시한 상태와 열린 모바일 메뉴, 총 다섯 axe WCAG 2 A/AA, 2.1 AA 검사에서 위반 0개.
- `npm run test:mobile`: 112개 검사 통과. Pixel 7의 Chrome 터치 에뮬레이션과 Windows WebKit의 iPhone 13 뷰포트를 사용했습니다.
- `npm run test:media`: 45개 검사 통과. 데스크톱 Chrome, Pixel 7 Chrome, iPhone 13 뷰포트의 WebKit에서 풀브리드 크기·오버레이·무음 인라인 자동재생·실제 재생 시간 증가·화면 밖 정지·재진입 재생·수동 정지 유지·모션 감소와 수동 재생을 확인했습니다.
- 이전 클라우드 미리보기: 이전 정적 렌더링 버전의 30개 검사는 별도 이력입니다. 이번 핀·히어로 수정은 사용자의 로컬 서버 요청에 따라 로컬 PHP에만 적용했습니다.
- `npm audit`: 알려진 취약점 0개. 고정 의존성 버전은 package-lock.json에 있습니다.

## 직접 브라우저 확인

이야기 카드의 호버 clip-path 축소와 제목 밑줄을 제거했습니다. 사진만 1.07배 확대하고 카드·링크·사진 프레임·텍스트의 위치와 크기는 고정합니다. PC 정보도 사진 하단 24px에 흰색으로 겹쳐 배치하고 공통 그라데이션을 적용했습니다. Chrome·WebKit의 390·768·1440·1920px, 총 여덟 조합에서 호버 전후 네 영역의 좌표·크기 불변, 밑줄 없음, 하단 정보 배치, 모션 감소 시 확대 해제를 확인했습니다. 캡처는 `docs/screenshots/story-hover-overlay-1440.png`입니다.

히어로를 5초 간격 자동재생으로 변경했습니다. Chrome·WebKit에서 실제 자동 전환, 6번 → 1번 복귀, Lucide 일시정지·재생, 호버·키보드 초점·화면 밖·모바일 메뉴에서 정지와 복귀, 모션 감소 시 수동 탐색을 확인했습니다. 두 번째 섹션의 삶·계절·기억에는 프라이머리 배경 하이라이트를 넣고, 문장 마스크에 이어 색이 나타나도록 같은 스크롤 타임라인에 연결했습니다. 하이라이트가 문장 폭을 바꾸지 않도록 했으며 PC·모바일 정·역방향 마스크를 확인했습니다. 시작·중간·완료·시작으로 돌아온 네 상태의 제목 영역 접근성 검사에서도 위반 0개입니다.

모바일 메뉴 버튼의 테두리를 없애고 Lucide 세 줄이 X로 회전하도록 변경했습니다. 닫기 버튼·ESC·메뉴 링크 선택은 역방향 전환을 마친 뒤 닫습니다. 열린 로고와 버튼의 x/y/폭/높이를 헤더와 비교해 1px 미만 차이로 일치하는지 확인했습니다. ## 이전 버전 성능 실측

아래 수치는 이번 핀·히어로 수정 이전 버전의 기록입니다. 이번 변경 후 성능 점수로 주장하지 않습니다.

Lighthouse 13.6.0, headless Chrome, `http://127.0.0.1:8080/`, 기본 simulated throttling, 로컬 PHP 개발 서버의 gzip 응답을 사용했습니다. 아래는 단일 실험실 실행이며 사용자 실측 데이터가 아닙니다.

| 환경 | 성능 | 접근성 | LCP | CLS | TBT |
| --- | ---: | ---: | ---: | ---: | ---: |
| 모바일 / Slow 4G 시뮬레이션 | 100 | 100 | 0.90초 | 0.000 | 42ms |
| 데스크톱 / Lighthouse desktop preset | 100 | 100 | 0.32초 | 0.000 | 0ms |

성능 목표는 LCP 2.5초 이하, CLS 0.1 이하입니다. 모바일 LCP는 0.90초로 목표를 충족합니다. CLS는 목표를 충족합니다. TBT는 실험실 지표이며 INP가 아닙니다. 실제 사용자 INP 데이터는 없습니다. 위 수치는 로컬 원본 측정으로 클라우드 미리보기의 모바일 실사용 성능과 구분합니다.

상세 원본: `docs/lighthouse-mobile.report.html`, `docs/lighthouse-mobile.report.json`, `docs/lighthouse-desktop.report.html`, `docs/lighthouse-desktop.report.json`.

## 미확인 및 제한

- 실제 iPhone/iPad의 iOS Safari와 실제 Android 기기는 연결되지 않았습니다. Windows WebKit 및 Chrome 에뮬레이션을 실기 검증으로 보고하지 않습니다.
- 실제 모바일 키보드, VoiceOver·TalkBack의 전체 낭독, 실사용 INP는 미확인입니다. 폼은 고정 하단 버튼 없이 일반 문서 흐름으로 구현했습니다.
- 실제 운영 접수·데이터베이스·관리자 검토 API는 원본에 없었습니다. 따라서 저장 성공·실패·재시도 서버 시나리오는 해당하지 않습니다. 프론트의 처리 중 중복 동작 방지와 로컬 파일 실패 피드백만 구현했습니다.
- Apache/Nginx 운영 호스팅 설정은 안내를 제공했으나 이 환경에서 실제 배포하지 않았습니다.
- 별도 Sites 클라우드 미리보기 배포는 성공했습니다. 본인 계정 전용이라 실제 원격 브라우저는 로그인 안내까지 확인했습니다. 로그인 후 콘텐츠의 원격 실기 동작은 미확인입니다. 같은 렌더링 결과를 로컬 정적 서버에서 30개 항목으로 검증했습니다.
- 주민 이름·음식 이름·원고·해설·주민 영상·자막·확정 문의 창구는 미제공으로 준비 상태입니다.

자동 접근성 검사 통과는 모든 보조기기·실기 환경의 접근성 완전 검증을 의미하지 않습니다.
